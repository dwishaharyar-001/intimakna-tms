# Catatan Keputusan Desain — Intimakna TMS

Ringkasan keputusan yang disepakati saat penyusunan sistem (klariifikasi fullstack).

| # | Topik | Keputusan | Implikasi implementasi |
|---|---|---|---|
| 1 | Frontend stack | **React / Next.js** | `apps/web` dibangun dengan Next.js App Router + React 19; akses per halaman dibatasi sesuai peran. |
| 2 | Konversi Lead → Peserta | **Lead menjadi Peserta saat mereka mentransfer biaya training** | Dua titik: (a) `POST /leads/:id/enroll` mendaftarkan lead ke batch (dibuatkan participant bila belum ada + draf tagihan); (b) saat Finance mencatat pembayaran lunas (`PATCH /financials/revenues/:id` → `PAID`), lead tertaut / bercocok-cocok no. HP otomatis `CLOSED_WON`. |
| 3 | Refresh token | **Dibuat** (endpoint refresh + logout) | Refresh token opaque random 48-byte, disimpan sebagai hash SHA-256 di tabel `RefreshSession` (tambahan di luar schema awal), dikirim via HttpOnly cookie 7 hari, **dirotasi** tiap pemakaian (revoke + replace). |
| 4 | Perhitungan revenue batch | **Diatur kemudian** | Sementara: `revenue = Σ BatchRevenue.totalAmount`, `net = revenue − Σ BatchExpense`. Struktur sudah siap disesuaikan bila model korporat/paket disepakati. |
| 5 | Sertifikat & feedback | **Diatur nanti** | Field `certificateNo` & `feedbackScore` sudah ada di model `BatchParticipant`; belum ada endpoint/UI pengelolaannya. |
| 6 | Akun Super Admin | **Ditambahkan** (role `SUPER_ADMIN`) | Level tertinggi: tembus semua RBAC, kelola semua akun/peran (termasuk sesama SUPER_ADMIN), menu **Konfigurasi** `/settings` disiapkan sebagai kerangka — cakupan modul konfigurasi **akan didefinisikan berikutnya** (placeholder sementara, bukan fitur fiktif). |
| 7 | Status leads dinamis | **Pipeline dapat dikonfigurasi SUPER_ADMIN** | Status tidak lagi enum kaku: tabel `LeadStage` (label, urutan, sifat OPEN/WON/LOST) bisa diubah jumlah/urutan/namanya di `/settings`; halaman Leads Pipeline menjadi **Kanban drag-drop**; default `assignedToId` = akun sales yang login (selain sales: daftar semua sales aktif). |
| 8 | Master program + silabus | **Kelola nama, deskripsi & silabus (opsional)** di Konfigurasi | Kolom `syllabus` ditambahkan ke `TrainingProgram` (teks baris-per-materi); menu Konfigurasi Super Admin menyediakan tambah/ubah/hapus program lengkap (nama, kategori, harga, deskripsi, silabus); hapus diblokir bila program sudah dipakai batch. |
| 9 | Pengaturan Pelatihan | **Dua entitas: Kelas Reguler & Program Pelatihan**, keduanya bisa tambah/ubah/hapus | Istilah “Batch” di antarmuka diganti **“Kelas/Kelas Reguler”** (nama teknis `ProgramBatch` tetap). Menu Konfigurasi → bagian *Pengaturan Pelatihan* memuat dua manajer; endpoint `PATCH/DELETE /batches/:id` ditambahkan (hapus diblokir bila kelas masih punya peserta/tagihan/pengeluaran). |
| 10 | **In-House Training (harga paket)** | Kelas maupun Program bisa dilaksanakan **In-House di korporat**; harga menjadi **paket** (bukan per pax) | `ProgramBatch` menambah `deliveryType` (REGULAR/IN_HOUSE), `clientName`, `pricePerPax` (opsional, fallback harga program), `packagePrice`, `packagePaid`, `packagePaymentStatus`; `TrainingProgram` menambah `inHousePrice` (usulan harga paket). Tagihan per-peserta **tidak dibuat** untuk kelas In-House; pembayaran paket diatur Finance via `PATCH /financials/batches/:id/package`. Ringkasan profit batch otomatis memakai harga paket untuk In-House. |
| 11 | Binding Lead → Program/Kelas | **Lead baru dapat diikat ke Program dan/atau Kelas Reguler tertentu (opsional)** | `Lead` menambah `interestProgramId` & `interestBatchId` (FK opsional, **independen** — lihat koreksi #12). Kanban menampilkan chip 🎯 program/kelas pada kartu lead; binding bisa dikosongkan lagi. |
| 12 | **Koreksi model: Kelas Reguler ≠ Program** | **Kelas Reguler = menu training default INTIMAKNA (berdiri sendiri)**; **Program = materi custom untuk kebutuhan khusus (berdiri sendiri)** | Relasi `ProgramBatch.programId` **dihapus**; kelas memiliki data sendiri (`category`, `description`, `syllabus`, `pricePerPax`). Harga per peserta **wajib** untuk kelas reguler; draf tagihan memakai `pricePerPax`. Binding lead tetap mendukung keduanya secara **independen** (tanpa auto-derivasi/mismatch check). Hapus program kini dicek terhadap minat lead (bukan kelas). |
| 13 | Aktivitas follow-up leads | **Riwayat follow-up per lead** (Email/Call/WhatsApp/Tatap Muka/Lainnya) | Tabel `LeadActivity` + agenda `GET /activities/today`; **ubah status lead wajib disertai catatan aktivitas** (400 bila kosong), sedangkan **mencatat aktivitas tidak mengubah status**; konversi otomatis (lunas bayar/manual) membuat catatan sistem; UI: badge aktivitas + follow-up terdekat di Kanban, halaman Detail Lead berisi timeline & form. |
| 14 | Migrasi data alumni (dengan riwayat) | **Upload CSV/Excel di Konfigurasi (Super Admin), 1 orang boleh banyak baris program → digabungkan otomatis** | Endpoint `POST /alumni-import` (dry-run & aktual, `updateExisting`, maks 5.000 baris). Kolom: `nama*, telepon*, email, perusahaan, jabatan, program, tanggal, lokasi, kota`. Penggabungan orang via **telepon → email → nama+perusahaan**; setiap baris program menjadi riwayat (`BatchParticipant` COMPLETED); program yang belum ada **otomatis dibuatkan Judul Materi + Kelas** (kategori `Migrasi`, status Selesai, `pricePerPax` 0). Tanggal menerima `YYYY-MM-DD` atau `DD/MM/YYYY`. Template: `/templates/template-alumni.csv` & `.xlsx`. |
| 15 | **Judul Materi & Learning Path** | **Kelas Reguler = Judul Materi + Batch**; Learning Path = urutan Judul Materi berdasarkan **Level Number** (satu level boleh berisi beberapa materi) | Model baru `Material` (title, kategori, deskripsi, silabus, `levelNumber` dasar→advanced, `orderInLevel`, aktif). `ProgramBatch.materialId` (FK opsional, `SetNull`). Migrasi otomatis membentuk materi dari kategori kelas lama. Menu Konfigurasi → **Judul Materi & Learning Path** (CRUD + atur level/urutan + pratinjau jalur); form Kelas kini wajib memilih **Judul Materi** + mengisi **Nama Batch**; tampilan kelas di seluruh aplikasi memakai “Judul Materi · Level · batch”. Impor alumni otomatis membuat Judul Materi untuk program baru. |
| 16 | **Prospek marketing per materi/level** | Prospek = alumni yang **belum mengikuti** materi tertentu; default **mode prasyarat** (hanya alumni yang sudah menuntaskan level sebelumnya), bisa dialihkan ke “semua alumni” | Endpoint `GET /learning-path/coverage` (cakupan per level & materi) dan `GET /materials/:id/prospects?mode=prereq|all&search=` (daftar *sudah ikut* + *prospek* + kelas PLANNED terdekat). UI: menu **Prospek** (dua tabel, filter, **Ekspor CSV**, **Jadikan Lead** yang otomatis mengikat minat ke kelas berikutnya) dan badge **👥 sudah ikut · 🎯 prospek** di Konfigurasi → Learning Path. Seed demo: 8 alumni dengan sebaran materi berbeda (tidak semua materi diikuti) + 1 kelas lampau & 1 kelas akan datang per materi. |
| 17 | **Checklist Requirement Kelas/Program** | Dua kategori: **Default** (template, nilainya bisa diubah di Konfigurasi) & **Custom** (per kelas, bisa ditambah **saat kelas sedang berjalan**); hanya **peringatan** bila belum lengkap (tidak memblokir) | Tabel `RequirementTemplate` (judul, catatan, urutan, aktif) dan `BatchRequirement` (per kelas: kategori, judul, catatan, `isDone`, `doneAt`, `doneById`, urutan). Kelas baru **otomatis menyalin** item Default aktif (snapshot). API: CRUD template, `GET/POST /batches/:id/requirements`, `PATCH/DELETE /requirements/:id`. UI: manajer **Checklist Default** di Konfigurasi; kartu **Checklist Persiapan** di detail kelas (grup Default/Custom, centang + siapa/kapan, tambah custom, progress bar); badge **☑ n/m** di daftar Pelatihan; widget Dashboard **“Persiapan Kelas Terdekat”** (kelas PLANNED yang belum lengkap + H-n) dan **“Kalender Kelas”** bulanan (grid bulan berjalan, navigasi bulan lalu/berikutnya + tombol Hari ini) di bagian bawah Dashboard. Hak: ADMIN_TRAINING & TRAINING_SUPPORT (centang/tambah), SUPER_ADMIN penuh, peran lain melihat. |
| 18 | **Widget bisa diatur per user + paging** | Susunan widget per halaman **tersimpan per akun** (drag & drop + sembunyikan, tombol “Atur Widget”/Reset); jumlah baris daftar **diatur sendiri oleh pengguna** (bawaan 10) dengan tombol **‹ Previous / Next ›** | Tabel `UserPageLayout` (`userId + pageKey` unik, `layout` JSON) + API `GET/PUT /me/layout/:pageKey` (hanya layout milik user sendiri). Komponen `Pager` (rentang “1–10 dari N”) dan `WidgetBoard` (`components/widgets.tsx`) dengan **pengaturan ukuran per widget: lebar ¼/⅓/½/⅔/Penuh + tinggi S/M/L/Auto** (layout JSON menyimpan `{key,hidden,span,height}`, divalidasi server). Board terpasang di **semua halaman**: Dashboard, Keuangan, Konfigurasi, Pelatihan (Kelas & Program), Alumni, Prospek, Pengguna, Leads (form/Kanban/catatan), dan Detail Kelas (Ringkasan/Peserta & Checklist/Keuangan) — halaman Pelatihan kini memakai board dua widget menggantikan tab. ## Catatan lain

- MVP **standalone** (tanpa integrasi sistem eksternal), sesuai PRD.
- `MANAGEMENT` bersifat analitik read-only di sisi backend (endpoint mutasi tidak membuka role ini, kecuali manajemen pengguna).
- `AuditLog` mencatat seluruh mutasi penting + login/refresh.
